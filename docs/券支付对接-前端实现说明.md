# 券支付对接 - 前端实现说明

本文说明前端如何配合《券支付对接指引：三个券接口如何配合使用》完成确认页券支付流程。

---

## 一、已实现的接口与位置

| 接口 | 封装位置 | 调用时机 |
|------|----------|----------|
| **获取券规则** `coupon_rules` | `miniprogram/utils/couponApi.js` → `getCouponRules(cid, opts)` | 可选：选座页 onLoad 时调，用于展示本影院可用券类型（当前未在页面上调用，可按需在 seat-select 中调用） |
| **券详情** `coupon_detail` | `couponApi.js` → `getCouponDetail(cid, electronCode)` | 确认页「添加优惠券」弹窗内点击确认时：先调此接口校验该券是否可用（`couponAvailable === 2` 则提示不可用），再走 Supabase 绑定 |
| **添加券试算** `check_coupon` | `couponApi.js` → `checkCoupon(params)` | 确认页选择「券支付」且已选至少一张券时：用当前订单（cid、play_id、price、seat_num） + 已选券码（coupons 逗号分隔）调此接口，得到 balance、savedMoney、lackedEcode，用于展示「还需要支付」「已节省」及缺券提示 |
| **券支付下单** `order_create` | `couponApi.js` → `orderCreateWithCoupon(params)` | 确认页点击「立即支付」且支付方式为券支付时：传与 check_coupon 一致的 coupons + cash=balance，以及 cid、play_id、seat_id、lock_flag、out_trade_no、order_id、num、partner_buy_ticket_id 等 |

所有请求均通过现有 `dingxinRequest.post`，签名逻辑与 `apiSign.buildSignedParams` 一致。

---

## 二、确认页（confirm-pay）流程简述

1. **支付方式**：用户可选择微信支付、券支付、会员卡支付。
2. **优惠券区块**：展示「输入券码绑定」入口 + 已绑定券列表（卡片 + 方形多选框）。点击卡片可多选/取消，用于券支付时参与试算。
3. **选择券支付时**  
   - 未选券：合计下方「还需要支付」= 商品总计；底部「应付金额」= 总计。  
   - 已选券：自动调 `check_coupon`，用返回的 `balance` 作为「还需要支付」和底部「应付金额」，用 `savedMoney` 展示「已节省 xx 元」；若 `lackedEcode` 非空则展示红色缺券提示，并禁止支付直到用户调整选券或补券。
4. **立即支付（券支付）**  
   - 校验：已选至少一张券、无缺券提示、试算结果有效。  
   - 调 `orderCreateWithCoupon`，传当前选中的券码（与 check_coupon 一致）+ `cash = balance` + 订单相关参数。  
   - 成功：更新本地订单为已支付并轮询 pay_status，跳转取票页；失败则 toasts 提示。

订单参数来源：`orderData`（来自 `app.globalData.playOrder`），含 `cinema_id/cinema_num`（cid）、`play_id/cine_play_id`、`num`、`total`、`seat_id`、`lock_flag`、`out_trade_no`、`id`（orderId）等，均由选座页写入。

## 三、后端需对齐的要点

1. **下单接口路径**  
   前端当前写死为 `POST /nonmember/order_create`（见 `couponApi.orderCreateWithCoupon`）。若实际为 `lock-buy` 或其他路径，需在 `couponApi.js` 中把 `dingxin.post('/nonmember/order_create', p)` 改为实际 path。

2. **下单参数**  
   当前传参：`cid, play_id, seat_id, lock_flag, coupons, cash, out_trade_no, order_id, num, partner_buy_ticket_id`。若鼎新要求更多或更少字段、或字段名不同，需在 `_processCouponPay` 与 `orderCreateWithCoupon` 中同步修改。

3. **coupons 与 cash**  
   与《券支付对接指引》一致：下单时的 `coupons`（及格式）必须与最近一次 `check_coupon` 调用一致，`cash` 必须为该校验返回的 `balance`。

4. **仅卖品**  
   当前确认页为影票场景；若后续支持「仅卖品」，check_coupon 与下单均不传 `play_id/price/seat_num`，只传 `cid + goods + 券 + cash`，需在 `_getOrderParamsForCoupon` 与 `_fetchCheckCoupon` 中按场景分支。

## 四、文件清单

- `miniprogram/utils/couponApi.js`：券规则、券详情、check_coupon、order_create 封装。  
- `miniprogram/pages/confirm-pay/confirm-pay.js`：选支付方式、多选券、试算、缺券提示、券支付下单与跳转。  
- `miniprogram/pages/confirm-pay/confirm-pay.wxml`：优惠券区块（多选卡片）、合计区「已节省」「还需要支付」、缺券/试算中提示、底部应付金额（券支付时用 payRemain）。  
- `miniprogram/pages/confirm-pay/confirm-pay.wxss`：缺券提示、试算中、已节省等样式。
