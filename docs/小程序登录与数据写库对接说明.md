# 小程序登录与数据写库对接说明

本文档供在**其他微信小程序**中复用本项目的**登录与会话逻辑**，并汇总**所有与写库/更新相关的接口与调用链**。  
实现代码主要位于：`miniprogram/utils/auth.js`、`miniprogram/app.js`、`miniprogram/utils/supabase.js`。

---

## 一、架构概览

| 层级 | 作用 |
|------|------|
| **认证服务**（如 `https://auth.meicity.net`） | 微信静默登录（`code` 换 token）、手机号验证码、微信 `getPhoneNumber` 绑手机等；**用户/会话数据在该服务端落库**，小程序只调 HTTP。 |
| **Supabase REST**（`{supabaseUrl}/rest/v1/...`） | 业务表：订单、会员卡绑定、充值订单、反馈、券等；小程序用 **anon key 或 service role key** 直连 PostgREST。 |
| **鼎新等业务 HTTP**（`dingxinBaseUrl` 等） | 锁座、会员卡支付、绑卡等；**是否同步写你们自建库**由网关/后端决定。 |
| **支付**（如扫呗 `saopayBaseUrl`） | 拉起微信支付；订单状态更新可能由回调或小程序侧再补 `PATCH`。 |

**套用到新项目时**：至少需要替换 `authBaseUrl`、`supabaseUrl`、密钥、以及各业务域名；表结构需与下文一致或自行改字段映射。

## 二、登录与会话（复用核心）

### 2.1 本地存储（`auth.js`）

| Key | 含义 |
|-----|------|
| `access_token` | 认证服务下发的 Bearer，后续免签接口带 `Authorization: Bearer <token>` |
| `user` | 用户信息 JSON（含 `id`、`openid`、`phone`/`mobile` 等） |
| `need_phone` | 后端是否标记需要绑定手机 |
| `phone_login_done` | **仅当用户完成过「手机号验证/绑定」后为 true**；用于冷启动是否恢复「完整业务登录态」 |

### 2.2 全局状态（`app.js` 中 `globalData`）

| 字段 | 含义 |
|------|------|
| `supabaseUser` / `userinfo` | 当前用户（与 `public.users` 对齐的 id、phone） |
| `sessionReady` | 是否已完成 `_runSessionRestore` |
| `wxProfile` | `{ openid, unionid }` |
| `cardinfo` | 会员卡缓存（来自 `user_member_cards` 查询 + 可选鼎新详情） |
| `manualLogout` | 用户主动退出后为 `true`，**禁止静默登录把会话拉回** |

### 2.3 静默登录 `auth.silentLogin()`

1. `wx.login` 取得 `code`。
2. `POST {authBaseUrl}/auth/wechat-mp/login`，Body：`{ "code" }`。
3. 响应期望：`access_token`、`user`（可选）、`need_phone`。
4. 写入本地 `access_token`、`user`、`need_phone`。

### 2.4 手机号两种路径

**A. 验证码（Bearer 免签）：**

- `POST {authBaseUrl}/api/v1/send-otp` — 发验证码（Header：`Authorization: Bearer <access_token>`）。
- `POST {authBaseUrl}/api/v1/verify-login` — Body：`{ phone, code, openid? }`；成功后更新 `access_token`/`user`（见 `verifyLoginSigned`）。

**B. 微信 `getPhoneNumber`：**

- `POST {authBaseUrl}/auth/wechat-mp/bind-phone`，Body：`{ code }`（微信返回的 `code`），Header：`Authorization: Bearer <access_token>`。
- 成功后调用 `applyBindPhoneResult`**统一写 `globalData`、拉会员卡**。

### 2.5 会话恢复 `_runSessionRestore()`（`app.js`）

- 若 `manualLogout === true`：清空用户相关 `globalData`，`sessionReady = true`，非登录/绑手机页会 **`redirectTo` 登录页**。
- 否则先执行 `silentLogin()`，再判断：
  - **`hasPhoneLoginDone()` 且 `token` 且 `storedUser`** 才恢复 `supabaseUser`、`userinfo`，并拉 `getUserMemberCard`、可选 `cardApi.getCardDetail` 合并详情。
  - 否则**不恢复**完整用户态（避免仅静默登录就当已登录）。

### 2.6 登录页 `pages/login/login.js`（行为摘要）

- 已退出（`manualLogout`）→ 展示「开始登录」→ 用户点击后清 `manualLogout` 再走 `_doSilentLogin`。
- 已有 `token` + `storedUser` → `_completeSessionAndGoHome()`（写 `globalData`、`setPhoneLoginDone()`、拉卡、`reLaunch` 首页）。
- 仅静默成功 → 若 `result.user` 有值则同上；否则只结束 loading（**手机号在别处弹窗补全**）。

### 2.7 业务页门禁 `redirectToLoginIfNeeded()`

- 要求：`sessionReady` 且 `supabaseUser` 非空，且 `phone`/`mobile` 有值。
- 否则 Toast 并跳转登录页。

### 2.8 组件

| 组件 | 路径 | 职责 |
|------|------|------|
| `phone-login-modal` | `components/phone-login-modal/` | 手机号 + 验证码 + 协议；`verifyLoginSigned` 成功后写 `globalData`、拉卡、`triggerEvent('success')` |
| `get-phone-modal` | `components/get-phone-modal/` | 协议 + `getPhoneNumber`；必要时先 `silentLogin`，再 `bindPhoneWithWechatCode` + `applyBindPhoneResult` |

### 2.9 套用到新小程序的检查清单

- [ ] 配置 `app.globalData.authBaseUrl`（及微信后台合法域名）。
- [ ] 复制 `auth.js` 中请求路径与后端约定一致（或改路径）。
- [ ] 复制 `app.js` 中 `_runSessionRestore` 与 `phone_login_done` 逻辑。
- [ ] 登录页、弹窗组件、各页 `redirectToLoginIfNeeded` 与路由一致。
- [ ] 退出登录时调用 `auth.logout()` 并设 `manualLogout`（与现逻辑一致）。

## 三、Supabase 直连：写库 / 更新库（`miniprogram/utils/supabase.js`）

所有请求形态：`{supabaseUrl}/rest/v1` + 表路径；Header：`apikey` + `Authorization: Bearer <key>`（key 为 anon 或 service role，见 `getConfig()`）。

### 3.1 表与操作一览

| 表名 | 方法 | 封装函数 | 说明 |
|------|------|----------|------|
| `user_member_cards` | POST（Prefer: merge-duplicates） | `bindMemberCard` | 绑定会员卡（`user_id` 唯一合并） |
| `user_member_cards` | PATCH | `unbindMemberCard` | 解绑：`status=unbind`、`unbind_at` |
| `cinema_order_list` | POST | `createOrder` | 创建影票订单；插入后 PATCH 写 `out_trade_no` |
| `cinema_order_list` | PATCH | `updateOrder` | 更新订单字段（支付状态、锁座、总价等） |
| `card_new_recharge_order` | POST | `createCardRechargeOrder` | 会员卡新办/充值订单；再 PATCH `out_trade_no` |
| `card_new_recharge_order` | PATCH | `updateCardRechargeOrderPayState` | 按 `out_trade_no` 更新支付状态 |
| `user_feedback` | POST | `createFeedback` | 新增反馈 |
| `coupon_instance` | PATCH | `bindCoupon` | 绑券：写 `user_id` |
| `coupon_instance` | POST | `insertCouponFromDetail` | 按鼎新券详情插入一条券实例 |
| Storage `public-assets` | POST | `uploadFeedbackImage` | 上传反馈图片（`x-upsert`），路径 `wechat-users/{user_id}/...` |

### 3.2 RPC（POST，可能含业务侧写库）

| RPC | 说明 |
|-----|------|
| `rpc_calc_ticket_price_tx` | 算价（事务版）；是否写库取决于数据库函数实现 |
| `get_near_cinema_list` | 附近影院，一般为读 |

### 3.3 典型调用页面（便于追溯）

| 页面/场景 | 调用 |
|-----------|------|
| `play.js` / `imax.js` | `createOrder` |
| `seat-select.js` | `updateOrder`（锁座、`out_trade_no` 等） |
| `confirm-pay.js` | `updateOrder`、`insertCouponFromDetail`、`bindCoupon` |
| `order.js` | `updateOrder`（取消等） |
| `card-manage.js` | `createCardRechargeOrder`、`updateCardRechargeOrderPayState` |
| `feedback-add.js` | `uploadFeedbackImage`、`createFeedback` |
| `coupon-list.js` / `coupon-bind.js` | `insertCouponFromDetail`、`bindCoupon` |

`bindMemberCard` / `unbindMemberCard` 在工具层已封装；若业务改为**仅鼎新绑卡**，以 `cardApi` 注释为准（后端可能同步写 `user_member_cards`）。

## 四、认证服务上的写库（不在本仓库实现）

以下接口由 **`auth.meicity.net`（或你们自建等价服务）** 实现，**用户表、会话表在该服务端落库**：

- `POST /auth/wechat-mp/login`
- `POST /auth/logout`
- `POST /api/v1/send-otp`、`POST /api/v1/verify-login`
- `POST /auth/wechat-mp/bind-phone`、`/auth/wechat-mp/get-phone`
- 以及旧版 `POST /auth/phone/send-otp`、`/auth/phone/login`、`/auth/phone/bind` 等（见 `auth.js` 全文）

复用时需有**后端文档或 OpenAPI** 对齐字段与错误码。

## 九、安全与合规提示

- **勿把 service role key 打进小程序包体**用于生产；若需强 RLS，应改为用户 JWT 或后端代理。
- `authBaseUrl`、Supabase URL、支付密钥等应通过**可配置环境**管理，文档中勿提交真实密钥。
- 微信手机号、登录 `code` 需符合微信平台隐私与登录规范。
