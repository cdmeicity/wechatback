# 手机号登录改为「微信获取手机号」评估

本文档说明：当前「电话+验证码」注册/登录的组件与数据落点，以及若改为**微信「获取手机号」组件**需要改动的范围，便于做评估与排期。

---

## 一、当前方案：电话 + 验证码

### 1.1 涉及组件与页面

| 类型 | 路径 | 用途 |
|------|------|------|
| **弹窗组件** | `components/phone-login-modal/` | 手机号输入框 + 验证码输入框 + 发送验证码 + 登录；用于**未登录时**在排期/订单/IMAX 等页弹出 |
| **独立页面** | `pages/bind-phone/` | 绑定手机号页：手机号输入 + 验证码输入 + 获取验证码 + 绑定；用于静默登录后 `need_phone=true` 等需补填手机号的场景 |

**使用位置：**

- **phone-login-modal**：在 **play**、**order**、**imax** 三个页面的 wxml 中引用，通过 `show="{{showLoginModal}}"` 控制显隐；用户点「继续」或进入订单等需登录操作时，若未登录则弹出该弹窗。
- **bind-phone**：在 `app.json` 中配置为独立页面；入口为需要「绑定手机号」时跳转（如 `wx.navigateTo({ url: '/pages/bind-phone/bind-phone?from=play' })`），当前代码里未看到在 onLaunch 根据 `need_phone` 自动跳转，多为业务里按需跳转。

### 1.2 调用的接口（auth.js）

| 接口 | 方法 | 说明 |
|------|------|------|
| **静默登录** | `auth.silentLogin()` | `wx.login` 取 code → POST `/auth/wechat-mp/login`，返回 `access_token`、`user`、`need_phone` |
| **发送验证码** | `auth.sendOtpSigned(phone)` | 需先静默登录有 token；POST `/api/v1/send-otp`，Header `Authorization: Bearer <token>`，Body `{ phone }` |
| **验证码登录/注册** | `auth.verifyLoginSigned(phone, code, openid)` | 需先静默登录；POST `/api/v1/verify-login`，Body `{ phone, code, openid? }`，返回 `access_token`、`user` |
| **绑定手机（验证码）** | `auth.bindPhone(phone, code)` | 已静默登录且 `need_phone` 时；POST `/auth/phone/bind`，Body `{ phone, code }`（当前 bind-phone 页实际用的是 `verifyLoginSigned`，见下） |
| **微信 code 换手机号** | `auth.getPhoneFromWechatCode(code)` | 已存在；POST `/auth/wechat-mp/get-phone`，Body `{ code }`（getPhoneNumber 回调里的 code），返回 `{ phone }` 等 |

说明：**bind-phone 页面**当前并未调用 `auth.bindPhone`，而是与弹窗一致：`sendOtpSigned` + `verifyLoginSigned(phone, code, openid)`，相当于「验证码登录并绑定 openid」。

### 1.3 登录/绑定成功后的数据流

- **前端存储**：`auth` 将 `access_token`、`user` 写入本地；`user` 含 `id`、`phone` 等；并设置 `STORAGE_PHONE_LOGIN_DONE`、`STORAGE_NEED_PHONE`。
- **全局状态**：`app.globalData.supabaseUser` / `userinfo` 由 `user` 组装（含 `id`、`userId`、`user_id`、`phone`），供全站使用。
- **会员卡**：用 `supabase.getUserMemberCard(userId)` 查表 `user_member_cards`（`user_id`、`card_no`、`phone`、`status`、`extra_data`），结果写入 `app.globalData.cardinfo`。
- **后端/表**（由接口推断，具体以实际后端为准）：
  - 鉴权服务（如 auth.meicity.net）：`/auth/wechat-mp/login`、`/api/v1/send-otp`、`/api/v1/verify-login`、`/auth/wechat-mp/get-phone`、`/auth/phone/bind` 等，会维护**用户表**（含 openid、phone、id 等）。
  - Supabase：`user_member_cards` 表（user_id、card_no、phone、status、extra_data）；业务订单等用 `user_id` / `phone` 关联。

## 二、改为「微信获取手机号」需要改什么

微信侧：用户点击按钮 → 触发 `getPhoneNumber` → 回调里拿到 **code**（需后端用 code 向微信换手机号，新版不再直接给明文手机号）。

### 2.1 前端改动清单

| 项 | 说明 |
|----|------|
| **1. phone-login-modal 组件** | 去掉「手机号输入框 + 验证码输入框 + 发送验证码 + 登录」整块，改为一个**按钮**：`<button open-type="getPhoneNumber" bindgetphonenumber="onGetPhoneNumber">微信手机号快捷登录</button>`；在 `onGetPhoneNumber` 里取 `e.detail.code`，调用后端「用 code 换手机号并登录/绑定」的接口（见 2.2），成功后与现有一致：写 token/user、setPhoneLoginDone、更新 globalData、拉 cardinfo、triggerEvent('success')。协议勾选可保留。 |
| **2. bind-phone 页面** | 同样改为「微信获取手机号」按钮为主；若仅保留这一种方式，可去掉手机号/验证码输入和发送验证码逻辑，只保留一个 getPhoneNumber 按钮 + 协议 + 关闭。 |
| **3. auth.js** | 已有 `getPhoneFromWechatCode(code)`，仅把 code 发后端换手机号。若后端提供**一步到位**的接口（见下），可新增如 `loginWithWechatPhoneCode(code)`：POST 该接口，返回 `access_token`、`user`，内部写 token/user、setPhoneLoginDone 等；弹窗/页面只调这一方法即可。 |
| **4. 协议与错误** | 仍需在点击前校验「已同意协议」；`getPhoneNumber` 拒绝或失败时（如 `e.detail.errMsg` 含 cancel），提示「需要授权手机号才能登录」等。 |

### 2.2 后端需要提供的接口（评估用）

| 方案 | 接口约定 | 说明 |
|------|----------|------|
| **A. 一步到位（推荐）** | 如 `POST /auth/wechat-mp/login-with-phone`，Body `{ code }`，Header `Authorization: Bearer <静默登录 token>` | 后端用 code 向微信换手机号，再在己方用户表创建/更新用户并绑定 openid+phone，返回 `access_token`、`user`。前端只发一次请求，逻辑最简单。 |
| **B. 两步** | ① 现有 `POST /auth/wechat-mp/get-phone` 用 code 换手机号；② 再调「用手机号绑定/登录」的接口（如带 phone 的 bind 或 login） | 前端先 `getPhoneFromWechatCode(code)` 拿到 phone，再调绑定/登录接口；若当前没有「仅用 phone 不校验验证码」的绑定接口，需要后端新增或改规则。 |

建议与后端确认：是否已有或可新增「仅凭 getPhoneNumber 的 code 完成登录/绑定并返回 token+user」的接口；若有，前端以方案 A 为主即可。

### 2.3 数据与表

- **用户表**（鉴权服务）：仍需有 `phone`、openid 等字段；由「微信 code 换手机号」得到 phone 后写入/更新，与现有一致，无需改表结构，仅写入方式从「验证码校验」改为「微信 code 解密」。
- **Supabase / user_member_cards**：仍用 `user_id`、`phone` 查询和展示，逻辑不变；无需改表。
- **恢复登录态**：仍依赖 `STORAGE_PHONE_LOGIN_DONE`、`user`、token，与现在一致；只需保证新接口返回的 `user` 结构与现有一致（含 `id`、`phone`）。

## 三、小结（给评估用）

| 类别 | 内容 |
|------|------|
| **当前** | 两处 UI（phone-login-modal 弹窗 + bind-phone 页），均用「手机号 + 验证码」；接口为 sendOtpSigned + verifyLoginSigned（及可选 bindPhone）；登录后写 token/user、更新 globalData、拉 user_member_cards。 |
| **改微信获取手机号** | 两处 UI 改为「获取手机号」按钮 + getPhoneNumber 回调；auth 新增或复用「code 换手机号并登录」的调用；后端需提供「用 getPhoneNumber 的 code 完成登录/绑定并返回 token+user」的接口（推荐一步到位）。 |
| **数据与表** | 用户表仍存 phone/openid，来源从验证码改为微信 code；Supabase 与业务侧无需改表，仅登录/绑定入口从验证码改为微信手机号。 |

若需要，我可以再按「第一步只改弹窗、保留 bind-phone 验证码」或「两处一起改」拆一版具体改动步骤（含改哪些文件、哪些行）。
