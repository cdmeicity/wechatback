# 改动总结（本轮会话）

以下为本轮对话中已落地的代码改动与文档更新。

---

## 一、已完成的代码改动

### 1. 登录页「再点授权」报错修复（bindPhoneWithWechatCode）

- **问题**：第一次取消微信手机号授权后，再次点击授权能拿到 `getPhoneNumber:ok` 和 code，但报错 `t.bindPhoneWithWechatCode is not a function`。
- **原因**：`auth.js` 中未实现并导出 `bindPhoneWithWechatCode`，登录页调用了不存在的方法。
- **改动**：在 **`miniprogram/utils/auth.js`** 中新增 **`bindPhoneWithWechatCode(code)`**：
  - 请求 `POST /auth/wechat-mp/bind-phone`，Body `{ code }`，Header `Authorization: Bearer <token>`；
  - 成功后将返回的 `user`、`access_token` 写入本地 storage，并设置 `STORAGE_NEED_PHONE = false`；
  - 增加 `[bind-phone]` 日志便于排查。

---

### 2. 绑定会员卡：手机号不一致时禁止绑卡

- **问题**：提示「会员卡绑定手机号和当前登录手机号不相符」后，用户点确定仍会继续调用绑卡接口。
- **要求**：必须手机号一致才能绑卡，不一致时不允许绑。
- **改动**：**`miniprogram/pages/card-manage/card-manage.js`** 中，在 `_doVerifyAndBind` 内：
  - 当 `cleanCardPhone && cleanPhone !== cleanCardPhone` 时，不再弹窗让用户「确定后继续」；
  - 改为：关闭 loading，打日志「③ 手机号不相符，禁止绑卡」，Toast「会员卡绑定手机号与当前登录手机号不一致，无法绑定」，直接 **return**，不调用后端 `card_bind`。

---

### 3. 登录页：静默登录 + 三表更新后跳主页

- **要求**：在微信静默登录和 Supabase 静默登录按约定完成，且后端成功更新 **users、user_profiles、user_price_scheme** 后，再跳转到主页。
- **改动**：**`miniprogram/pages/login/login.js`**  
  - **onLoad**：若已有 token 且 `!needPhone` 且已有 `storedUser`，视为已登录且已绑手机，直接调用 **`_completeSessionAndGoHome()`** 恢复 session 并 `wx.reLaunch` 到主页。  
  - **`_doSilentLogin`**：静默登录成功后，若 `!result.needPhone && result.user`，认为后端已在登录时更新三表，同样调用 **`_completeSessionAndGoHome()`** 跳主页。  
  - 新增 **`_completeSessionAndGoHome()`**：用 `auth.getUser()` 拼好 `supabaseUser`，写入 `app.globalData.supabaseUser` / `userinfo`，`manualLogout = false`，`auth.setPhoneLoginDone()`，有 `userId` 时拉会员卡写 `app.globalData.cardinfo`，最后 **`wx.reLaunch('/pages/index/index')`**。  
  - **bind-phone 成功**：逻辑不变，仍写 globalData、拉会员卡、Toast 后跳主页；在成功时的 LOG 中注明「后端已更新 users / user_profiles / user_price_scheme」。

### 4. 未绑手机时弹窗获取手机号方案

- **需求**：当 `users.phone` 为空时，在 IMAX 点击排期、Play 点击排期、Order 页、User（mypage）页不跳转登录页，而是弹出与登录页相同的微信获取手机号组件，完成 bind-phone 及与登录页一致的后续更新（globalData、setPhoneLoginDone、cardinfo 等）；不授权成功则停留在当前页、不能进入下一页。
- **文档**：**`docs/未绑手机时弹窗获取手机号方案.md`**  
  - 约定了触发时机：  
    - **IMAX / Play**：仅在**用户点击场次（排期）时**（`onShowtimeTap`）检查并弹窗，进入页不弹；  
    - **Order / User**：**点击进入该页 + 页面加载时**（onLoad / onShow）检查，无电话弹窗，有电话即默认登录成功。  
  - 只弹窗不跳转；不授权成功则停留在当前页不能进入下一页（IMAX/Play 不能进选座）。  
  - 技术方案：抽 `auth.applyBindPhoneResult(data)`、新建组件 `get-phone-modal`、四页 + 登录页改造方式。  
- **状态**：方案已定并已按你确认的细节更新文档，**尚未按该文档写代码**（抽 applyBindPhoneResult、新建 get-phone-modal、改 imax/play/order/user 及登录页）。
