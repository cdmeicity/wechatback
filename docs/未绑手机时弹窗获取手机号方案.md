# 未绑手机时弹窗获取手机号方案（待确认后实施）

## 一、需求简述

当 **users.phone 为空**（已静默登录但未绑定手机号）时，**不跳转登录页**，在约定时机**弹出与登录页相同的微信获取手机号组件**；授权成功后执行与登录页一致的 **bind-phone + 后续更新**。若用户**不授权成功**，则**停留在当前页，不能进入下一页**。

| 页面 | 检查时机（何时弹窗） | 有电话时 | 无电话时 | 不授权时 |
|------|----------------------|----------|----------|----------|
| **IMAX** | **点击某个场次（排期）时**（`onShowtimeTap`） | 正常走选座/下单 | 弹窗，不进入选座 | 停留在排期页，不能进入选座 |
| **Play（排期）** | **点击某个场次（排期）时**（`onShowtimeTap`） | 正常走选座/下单 | 弹窗，不进入选座 | 停留在排期页，不能进入选座 |
| **Order（订单）** | **点击进入该页 + 页面加载时**（`onLoad` / `onShow`） | 默认登录成功，正常展示订单 | 弹窗 | 停留在订单页，不展示后续能力 |
| **User（我的 / mypage）** | **点击进入该页 + 页面加载时**（`onLoad` / `onShow`） | 默认登录成功，正常展示我的 | 弹窗 | 停留在我的页，不展示后续能力 |

- **只弹窗，不跳转登录页**。不授权成功则一直停留在当前页，不能进入下一页（IMAX/Play 不能进选座，Order/User 有电话才算登录成功）。
- **前提**：仅当「已登录（有 token / supabaseUser）且 phone 为空」时弹窗；若未登录（无 token），仍保持**跳转登录页**不变。

---

## 二、登录页当前流程（与弹窗需保持一致的部分）

以下流程在方案中会**复用**，保证与登录页一致。

1. **前置**：有 token（无则先静默登录），用户点击按钮并授权。
2. **调接口**：`auth.bindPhoneWithWechatCode(code)` → 后端 POST `/auth/wechat-mp/bind-phone`，更新 **users**（及约定下的 user_profiles、user_price_scheme）。
3. **成功后的前端更新**（与登录页完全一致）：
   - 用返回的 `data.user`（或 `auth.getUser()`）拼出 `supabaseUser`（含 `id / userId / user_id / phone` 等）。
   - `app.globalData.supabaseUser = supabaseUser`，`app.globalData.userinfo = supabaseUser`。
   - `app.globalData.manualLogout = false`。
   - `auth.setPhoneLoginDone()`。
   - 若有 `userId`：`supabase.getUserMemberCard(userId)` → `app.globalData.cardinfo`；否则 `app.globalData.cardinfo = null`。
4. **登录页独有**：Toast「登录成功」后 `wx.reLaunch('/pages/index/index')`。  
   **弹窗场景**：不 reLaunch，改为关弹窗 + 触发页面回调（如刷新订单/用户信息等）。

## 三、技术方案概览

### 3.1 抽「绑定成功后的统一逻辑」

在 **`miniprogram/utils/auth.js`**（或单独工具文件）中新增：

- **`applyBindPhoneResult(data)`**（或类似命名）  
  - 入参：`bindPhoneWithWechatCode` 的返回 `data`。  
  - 内部完成：用 `data.user` / `auth.getUser()` 拼 `supabaseUser`，写 `app.globalData.supabaseUser` / `userinfo`，`manualLogout = false`，`auth.setPhoneLoginDone()`，按 `userId` 拉取并写入 `app.globalData.cardinfo`。  
  - 不包含跳转或 Toast，仅做状态更新。

这样登录页和弹窗都：先 `auth.bindPhoneWithWechatCode(code)`，再 `auth.applyBindPhoneResult(data)`，保证 **users.phone 的更新** 以及 **其它在登录页时的更新字段** 完全一致。

### 3.2 新建「微信手机号授权」弹窗组件

- **组件名**：例如 `get-phone-modal`（与现有 `phone-login-modal` 验证码弹窗区分）。
- **UI / 交互**（与登录页对齐）：
  - 协议勾选（《用户服务协议》《隐私政策》），未勾选时点击按钮先弹窗提示，勾选后再次点击才调起授权。
  - 主按钮：`open-type="getPhoneNumber"`，`bindgetphonenumber="onGetPhoneNumber"`。
  - 授权失败 / 无 code：Toast 提示，不关弹窗。
- **逻辑**：
  - 无 token 时先调 `auth.silentLogin()`，再继续。
  - 拿到 code 后：`wx.showLoading` → `auth.bindPhoneWithWechatCode(code)` → `auth.applyBindPhoneResult(data)` → `wx.hideLoading`，Toast「绑定成功」，`triggerEvent('success')`，由页面关弹窗并刷新。
  - 失败：`wx.hideLoading`，Toast 错误信息。
- **属性**：`show: Boolean`；**事件**：`close`、`success`（绑定成功时）。

### 3.3 四页改造方式

- **IMAX**（`imax.js` / `imax.wxml`）  
  - **进入页**：`onShow` 仅做「未登录（无 token）」时 `redirectTo` 登录页；**不**在进入时因无手机弹窗或跳转。  
  - **点击场次（排期）**：在 `onShowtimeTap` **开头**判断：若已登录但 **phone 为空**，则 `setData({ showGetPhoneModal: true })` 并 **return**（不创建订单、不跳选座）。用户必须授权成功后再点一次该场次才能进入选座。  
  - 引入 `get-phone-modal`，`show="{{showGetPhoneModal}}"`，`bind:success` 关弹窗并 `setData({ showGetPhoneModal: false })`（用户可再次点击排期继续）。

- **Play**（`play.js` / `play.wxml`）  
  - **进入页**：`onLoad` 仅做「未登录（无 token）」时 `redirectTo` 登录页；不在进入时因无手机弹窗。  
  - **点击场次（排期）**：在 `onShowtimeTap` **开头**判断：若已登录但 **phone 为空**，则弹 `showGetPhoneModal` 并 **return**，不进入选座。  
  - 引入 `get-phone-modal`，`bind:success` 关弹窗。

- **Order**（`order.js` / `order.wxml`）  
  - **点击进入 + 加载**：`onLoad` 与 `onShow` 都检查。若**无 token** → 仍 `redirectTo` 登录页。若**有 token 但 phone 为空** → 弹 `showGetPhoneModal`，不 redirect；**有 phone** → 默认登录成功，正常拉订单。  
  - `bind:success` 关弹窗并重新拉订单列表。

- **User（我的 / mypage）**（`user.js` / `user.wxml`）  
  - **点击进入 + 加载**：`onLoad` / `onShow` 都检查。无 token → redirect 登录页；有 token 无 phone → 弹窗；有 phone → 默认登录成功，正常展示我的。  
  - `bind:success` 关弹窗并 `refreshUser()`。

### 3.4 与 redirectToLoginIfNeeded 的配合

- **Order / User**：在 onLoad/onShow 中，若调用 `redirectToLoginIfNeeded()` 因「无手机」返回 false，**不**执行 `redirectTo`，改为 `setData({ showGetPhoneModal: true })`。无 token 时仍保持原有「请先登录」并跳转登录页。
- **IMAX / Play**：进入页仍可按需调用 `redirectToLoginIfNeeded()`（仅无 token 时跳转）；不在进入时因无手机弹窗，只在 **onShowtimeTap** 内判断无手机则弹窗并 return。

## 四、登录页改动

- 登录页在 `onGetPhoneNumber` 成功分支中：  
  - 仍先 `auth.bindPhoneWithWechatCode(code)`；  
  - 然后改为调用 `auth.applyBindPhoneResult(data)`，不再重复写 globalData/setPhoneLoginDone/cardinfo 的代码；  
  - 最后保留 Toast「登录成功」+ `wx.reLaunch('/pages/index/index')`。

这样「后续 users.phone 的更新动作，还有其它在登录页面时的更新字段」全部集中在 `applyBindPhoneResult`，登录页与四页弹窗行为一致。

## 五、小结（已按确认更新）

| 项 | 说明 |
|----|------|
| **IMAX / Play** | 仅在**用户点击场次（排期）时**检查 phone；无手机则弹窗并 **return**，不进入选座；不授权成功则一直停留在排期页，不能进入下一页。 |
| **Order / User** | **点击进入该页或页面加载时**（onLoad / onShow）检查；无手机弹窗，有电话即默认登录成功。只弹窗，不跳转登录页。 |
| **不授权时** | 只弹窗、不跳转登录页；不授权成功则停留在当前页，不能进入下一页（IMAX/Play 不能进选座）。 |
| **弹窗内容** | 与登录页相同的微信获取手机号组件（协议 + `getPhoneNumber` 按钮）。 |
| **授权成功后** | `bindPhoneWithWechatCode` → `applyBindPhoneResult`，关弹窗并刷新当前页（Order 重拉订单，User 刷新用户信息；IMAX/Play 用户可再次点击排期进入选座）。 |
| **复用与维护** | 统一逻辑放在 `auth.applyBindPhoneResult`，登录页与四页弹窗共用。 |

确认无误后按此方案实施：抽 `applyBindPhoneResult`、新建 `get-phone-modal`、改 IMAX（onShowtimeTap）/ Play（onShowtimeTap）/ Order（onLoad+onShow）/ User（onLoad+onShow）+ 登录页。
