# 订单二次支付：接口要求与说明

本文说明「同一笔订单再次发起支付」（订单列表里点「马上支付」）的接口约定、前端实现要点，以及可能遇到的问题。

---

## 一、二次支付流程（前端）

1. 用户在**订单页**「未付款」或「全部」里看到待支付订单，点击 **马上支付**。
2. 前端用该订单的 **out_trade_no** 调 `getOrderByOutTradeNo(outTradeNo)` 拉取**完整订单**（`cinema_order_list` 单条）。
3. 若订单不存在或已支付，提示并结束；否则将订单写入 `app.globalData.playOrder`，跳转 **确认支付页** `/pages/confirm-pay/confirm-pay`。
4. 确认支付页从 `playOrder` 取 `out_trade_no`、金额等，调 **扫呗 mini-pay**（与首次支付同一接口），再调起微信收银台。
5. 支付成功后的轮询、跳转影票详情与首次支付一致。

---

## 二、接口对「同一订单」的要求

### 2.1 支付接口：POST /api/payment/mini-pay（扫呗）

| 参数 | 说明 | 二次支付时的取值 |
|------|------|------------------|
| **terminal_trace** | 商户订单号，唯一标识一笔业务订单 | **必须与订单的 out_trade_no 一致**，不能改 |
| **total_fee** | 订单金额（分） | **必须与订单应付金额一致**（订单 total×100 取整） |
| terminal_time | 终端交易时间 | 当前时间 yyyyMMddHHmmss，每次可不同 |
| open_id、sub_appid 等 | 用户与小程序标识 | 与首次支付规则相同 |

要点：

- **同一订单多次发起支付**：使用**同一个 out_trade_no** 作为 `terminal_trace` 是允许的（例如用户第一次取消支付，第二次再点「马上支付」）。
- 后端/微信侧会对同一 `terminal_trace` 做处理：若已支付则不应重复扣款；若未支付则可能返回新的 prepay_id，用户再次调起收银台即可。
- **金额必须一致**：`total_fee` 必须等于该订单的应付金额（分），否则可能对账异常或风控。

### 2.2 订单数据来源

- 订单列表来自 **cinema_order_list**（按 openid、order_channel、phone 筛选）。
- 二次支付前必须用 **out_trade_no** 再查一次完整订单：`getOrderByOutTradeNo(outTradeNo)`，拿到整行后再传给确认支付页（通过 `playOrder`）。
- 这样做的原因：列表里只做了展示用转换，没有保留完整订单字段；确认支付页需要 `order.total`、`order.out_trade_no`、`order.movie_name` 等完整信息。

## 三、同一订单发起二次支付可能遇到的问题

### 3.1 订单没有 out_trade_no

- **现象**：订单列表里该订单的 `out_trade_no` 为空，点「马上支付」会提示「订单号不存在，无法支付」。
- **原因**：创建订单后，只有在选座页走到「非会员微信支付」或「非会员大于第三方停售」等分支时，才会把 `out_trade_no` 写入 `cinema_order_list`。若用户从未进入过这些流程（例如只创建了订单就离开），则库里可能没有 `out_trade_no`。
- **处理**：前端已做校验，无 `out_trade_no` 不发起支付并提示。若业务上希望这类订单也能支付，需在选座或订单列表处增加「为订单生成并回写 out_trade_no」的逻辑（与当前 seat-select 里 N7/NL3 的写回方式一致）。

### 3.2 订单已支付仍点「马上支付」

- **现象**：用户已付过款，再次从订单列表点「马上支付」。
- **处理**：在订单页 `onPay` 里，用 `getOrderByOutTradeNo` 拿到订单后先看 `pay_status`，若为 `SUCCESS` 或 `PAID` 则提示「订单已支付」并刷新列表，不跳转确认支付页。前端已按此实现。

### 3.3 同一订单多次调 mini-pay（未支付）

- **现象**：用户第一次调起微信支付后取消，再点「马上支付」，用同一 `out_trade_no` 再次请求 mini-pay。
- **接口预期**：后端/微信允许同一商户订单号多次获取预支付会话（每次可能新的 prepay_id）。只要最终只成功支付一次，后端根据回调将订单状态置为已支付即可。
- **注意**：`total_fee`、`terminal_trace` 必须与该订单一致，避免重复扣款或对账错误。

### 3.4 金额不一致

- **现象**：确认页展示的金额或优惠券扣减与订单创建时不一致，导致 `total_fee` 与订单 `total` 不一致。
- **建议**：二次支付时以**当前订单行里的 total** 为准计算 `total_fee`（total×100 取整），不要用页面临时计算的「合计」。确认支付页 onLoad 时已用 `order.total` 初始化，只要 `playOrder` 是刚查出来的订单即可。

## 四、前端实现要点（已实现）

- **订单页**  
  - 「马上支付」绑定 `onPay`，传入 `data-out-trade-no`（及可选 `data-order-id`）。  
  - `onPay`：校验 `out_trade_no` → `getOrderByOutTradeNo` → 校验订单存在且未支付 → `app.globalData.playOrder = order` → `wx.navigateTo('/pages/confirm-pay/confirm-pay')`。

- **确认支付页**  
  - 与首次进入时一致：从 `app.globalData.playOrder` 读订单，用 `order.out_trade_no` 作为 `terminal_trace`，用 `order.total` 计算 `total_fee`，调 `saopayRequest.miniPay` 后调起微信支付，支付成功后轮询 `getOrderByOutTradeNo` 查 `pay_status`，为 SUCCESS 后跳转影票详情。

- **订单列表数据**  
  - 列表接口返回的每条订单需包含 `out_trade_no`（或前端展示用的 `outTradeNo`），以便「马上支付」时传入并拉取完整订单。

## 五、小结

| 问题 | 接口/约定 | 前端处理 |
|------|-----------|----------|
| 同一订单能否多次发起支付？ | 可以，`terminal_trace` 保持为订单的 out_trade_no | 已支持：订单页点「马上支付」→ 拉单 → 跳确认页 → 调 mini-pay |
| 金额是否必须一致？ | 必须一致，用订单 total 转分 | 确认页用 `playOrder.total` 计算 total_fee |
| 订单已支付再点？ | 后端不应重复扣款 | 拉单后若 pay_status 为 SUCCESS/PAID 则提示并刷新，不跳转 |
| 订单没有 out_trade_no？ | 无法调起支付（需要订单号） | 校验无 out_trade_no 时提示「订单号不存在，无法支付」 |

以上为当前「订单二次支付」的接口要求与实现说明，可与后端/扫呗约定对齐使用。
