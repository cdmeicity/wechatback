# 购票关键页面：返回与跳转逻辑

本文档描述「排期 → 选座 → 支付 → 取票」流程中，各关键页面的**进入方式、返回/关闭行为、跳转规则**，供抖音小程序、App 等端对照实现，保证与微信小程序行为一致，避免订单/选座异常。

---

## 一、购票流程与页面栈（概念）

```
首页/影片详情 → 排期(play) → 选座(seat-select) → 确认支付(confirm-pay) → 取票(ticketinfo)
                    ↓                ↓                    ↓
                新建订单         更新座位/锁座           支付成功
```

**三种跳转方式（微信小程序术语，其他端请对照）：**

| 方式 | 微信 API | 含义 | 其他端建议对照 |
|------|----------|------|----------------|
| 压栈 | `navigateTo` | 保留当前页，打开新页；可返回上一页 | 普通 push / 打开新页面 |
| 替换 | `redirectTo` | 关闭当前页，打开新页；返回回到「上上一页」 | replace / 替换当前页 |
| 清栈 | `reLaunch` | 关闭所有页面，只保留新页；无法返回到任何旧页 | 清空栈再打开 / 单页模式 |

---

## 二、各关键页面说明

### 1. 排期页（play）

| 项 | 说明 |
|----|------|
| **进入方式** | 仅从首页/影片详情等入口 `navigateTo` 进入（带影院、影片等参数） |
| **返回/关闭** | 左上角返回：**navigateBack**（回到上一页，如影片详情或首页） |
| **去选座** | 用户选择场次并点「继续」→ 后端**新建订单** → 将订单写入全局（如 globalData.playOrder），并带 `playId、orderId、outTradeNo` **navigateTo** 选座页。 |

**规则要点**：去选座前必须先建单，且把「当前订单」放进全局，供选座页校验。

---

### 2. 选座页（seat-select）

| 项 | 说明 |
|----|------|
| **合法进入方式** | **仅允许**从排期页(play)在「新建订单」之后 **navigateTo** 进入，且 URL 带 `playId、orderId、outTradeNo`。 |
| **进入校验（必做）** | onLoad 时校验：① URL 有 `orderId`；② 全局中有「当前购票订单」（如 `globalData.playOrder`）；③ 该订单的 `id` 与 URL 的 `orderId` 一致。**三者缺一或不一致** → 视为非法入口，**清栈并跳首页**（即 reLaunch 首页）。 |
| **返回/关闭** | 左上角返回：**navigateBack**（回到排期页，可重新选场次或放弃本单）。 |
| **去支付** | 选座确认后：**navigateTo** 确认支付页(confirm-pay)。若选座页内直接完成支付（如会员卡支付），见下条。 |
| **支付成功（选座页内）** | 无论轮询到 pay_status=SUCCESS 或超时，均用 **reLaunch** 打开取票页（带 `out_trade_no`）；无订单号时 **reLaunch** 订单列表/订单页。**禁止**用 redirectTo，否则用户可从取票页返回到选座页。 |

**规则要点**：选座页 = 仅「从 play 新建订单后」这一条链路能进；支付成功离开选座/支付流程时一律清栈进取票或订单页。

---

### 3. 确认支付页（confirm-pay）

| 项 | 说明 |
|----|------|
| **进入方式** | 仅从选座页 **navigateTo** 进入（依赖全局订单数据）。订单不存在时提示并 **navigateBack**。 |
| **返回/关闭** | 左上角返回：**navigateBack**（回到选座页，可改座或换支付方式）。 |
| **支付成功** | 轮询到 pay_status=SUCCESS 或超时 → **reLaunch** 打开取票页（带 `out_trade_no`）；订单号缺失时 **reLaunch** 订单页。**禁止**用 redirectTo。 |
| **会员卡支付成功** | 无 out_trade_no 时 **reLaunch** 订单页；有则同上，**reLaunch** 取票页。 |

**规则要点**：支付成功后的出口必须是「清栈到取票页（或订单页）」，保证用户无法从取票页返回到选座/支付页。

---

### 4. 取票页（ticketinfo）

| 项 | 说明 |
|----|------|
| **进入方式** | ① 支付成功：由选座页或确认支付页 **reLaunch** 进入（带 `out_trade_no`），此时栈中只有取票页。② 从订单列表点某订单查看取票信息：可用 **navigateTo** 或 **redirectTo**（返回会回订单列表，不会回选座，无风险）。 |
| **返回/关闭** | **不依赖系统返回键**。左上角关闭：执行 **reLaunch 首页**（与「返回首页」一致）。 |
| **底部操作** | 提供两个明确出口：① **返回首页**：**reLaunch 首页**；② **我的订单**：**navigateTo** 订单列表/订单页。 |

**规则要点**：从「支付成功」进入的取票页，栈中不得保留选座/支付页，且离开方式仅「返回首页」「我的订单」两种，避免用户误返回到选座页导致重复选座、订单异常。

## 三、跳转方式速查表

| 场景 | 使用方式 | 说明 |
|------|----------|------|
| 排期 → 选座 | navigateTo | 新建订单后带 orderId/playId/outTradeNo 进入选座 |
| 选座 → 确认支付 | navigateTo | 正常进入支付页 |
| 选座 ← 确认支付 | 用户点返回 → navigateBack | 允许回到选座改座 |
| 选座 → 排期 | 用户点返回 → navigateBack | 放弃本单、重选场次 |
| **支付成功 → 取票** | **reLaunch** | 清空栈，只留取票页，禁止返回到选座/支付 |
| 支付成功但无订单号 → 订单页 | reLaunch | 同上，清栈到订单页 |
| 取票页 → 首页 | reLaunch | 左上角关闭、底部「返回首页」 |
| 取票页 → 订单列表 | navigateTo | 底部「我的订单」 |
| 选座页非法入口 | reLaunch 首页 | 未从 play 新建订单进入时 |

## 四、必须遵守的规则（各端统一）

1. **取票页不能返回到选座/支付页**  
   支付成功进入取票页时，必须用「清栈再打开取票页」（reLaunch），不能使用「替换当前页」（redirectTo），否则栈中仍会保留选座页，用户可点返回回到选座页再次选座，导致订单/座位异常。

2. **选座页仅允许从排期新建订单后进入**  
   选座页 onLoad 必须校验：存在「当前购票订单」且其 id 与 URL 的 orderId 一致；不满足则清栈跳首页。这样无论是从取票页误返回（在正确实现下不应发生）、还是从链接/分享直接打开选座页，都不会用旧订单或空订单选座。

3. **取票页提供明确出口**  
   取票页不依赖系统返回键，提供「返回首页」「我的订单」两个操作；左上角关闭与「返回首页」行为一致（清栈到首页）。

## 五、平台 API 对照（便于抖音/App 实现）

| 能力 | 微信小程序 | 抖音小程序 | App（示例） |
|------|------------|------------|-------------|
| 压栈打开新页 | wx.navigateTo | tt.navigateTo | 路由 push / 打开新 Activity 等 |
| 替换当前页 | wx.redirectTo | tt.redirectTo | 路由 replace |
| 清栈后打开 | wx.reLaunch | tt.reLaunch | 清空栈再 push / 单页栈 |
| 返回上一页 | wx.navigateBack | tt.navigateBack | 路由 pop / 返回 |

各端按上述语义实现即可，页面名与路由路径可按各自项目调整，**逻辑关系保持一致**。

## 六、文档版本与适用范围

- 基于当前微信小程序实现整理，适用于：微信小程序、抖音小程序、App 等需与「美承影院」购票流程对齐的端。
- 若有流程或规则变更，请同步更新本文档并通知各端。
