# 购票流程防返回与取票页方案

## 一、问题简述

当前流程：**play（排期）→ 点场次建单 → seat-select（选座）→ confirm-pay（支付）→ 支付成功 → ticketinfo（取票详情）**。

问题：支付成功后用的是 `wx.redirectTo` 打开 ticketinfo，页面栈里仍保留 **seat-select**。用户可以在取票页点左上角「返回」，退回到选座页，再次选座并提交，导致**同一订单被重复选座/更新**，订单失效或座位冲突。

---

## 二、方案目标

1. **取票页（ticketinfo）不能返回到选座/支付页**，从根源上避免「退回选座再选一次」。
2. 取票页提供明确出口：**返回首页**、**我的订单**，而不是依赖系统返回键。

---

## 三、推荐方案（两大部分）

### 1. 支付成功跳取票页：用 reLaunch 替代 redirectTo

**思路**：支付成功进入 ticketinfo 时，不再用 `redirectTo`（只替换当前页，栈里还有 seat-select），改为 **`wx.reLaunch`**。  
`reLaunch` 会**关闭所有页面**再打开目标页，这样栈里只有 ticketinfo，用户无法通过返回键回到选座或支付页。

**需要改动的入口（全部改为 reLaunch 到 ticketinfo，缺订单号时 reLaunch 到订单页）：**

| 位置 | 文件 | 说明 |
|------|------|------|
| 支付成功轮询到 SUCCESS 后跳转 | `confirm-pay/confirm-pay.js` | `_redirectToTicketinfo()` 内：`wx.redirectTo` → `wx.reLaunch`；订单号缺失时 `wx.redirectTo('/pages/order/order')` → `wx.reLaunch` |
| 选座页会员卡支付成功 / N7 出票成功 | `seat-select/seat-select.js` | `_navigateToTicketInfoPage()`：两处 `wx.redirectTo` → `wx.reLaunch`（ticketinfo 与 order） |
| 选座页会员卡支付轮询 M6.5 超时/SUCCESS | `seat-select/seat-select.js` | `_startM65PayStatusPoll` 里 setTimeout、`_checkM65OrderStatusOnce` 里：`wx.redirectTo(ticketinfo)` → `wx.reLaunch(ticketinfo)` |

**效果**：

- 从「支付成功」或「选座页内支付成功」进入 ticketinfo 时，栈被清空，**无法返回到 seat-select / confirm-pay**。
- play、seat-select、confirm-pay 之间的返回逻辑**不用改**：用户仍可从支付页返回选座改座、从选座返回排期，只有「付款完成后」的出口被收口到 reLaunch。

---

### 2. ticketinfo 取票页：不依赖返回键，底部增加两个按钮

**思路**：  
取票页作为购票流程的**终点页**，不鼓励用户点左上角返回（且 reLaunch 后栈只有一页，点返回会直接退出小程序）。因此：

- **保留左上角关闭/返回**：可保留现有 `onClose`，但行为改为「返回首页」或「我的订单」（见下）。
- **底部增加两个主操作**（在现有「承德美承影业有限公司」上方或同排）：
  - **「返回首页」**：`wx.reLaunch({ url: '/pages/index/index' })`  
    清栈回首页，避免再回到任何购票中间页。
  - **「我的订单」**：`wx.navigateTo({ url: '/pages/order/order' })` 或 `/pages/order-list/order-list`（以你实际「我的订单」入口为准）  
    方便用户继续查看/管理订单。

**onClose（左上角）建议**：  
当前是 `wx.navigateBack({ fail: () => wx.switchTab({ url: '/pages/index/index' }) })`。  
改为与「返回首页」一致更简单：**直接 `wx.reLaunch({ url: '/pages/index/index' })`**，这样无论是否 reLaunch 进取票页，行为统一，且不依赖 tabBar。

**小结**：

- **哪些页面「不能返回」**：  
  不是禁止某个页面的返回键，而是**付款成功后进入的 ticketinfo 不再处于「选座/支付」之上**——通过 reLaunch 清栈实现，所以**从 ticketinfo 无法返回到 seat-select/confirm-pay**。
- **ticketinfo 的出口**：  
  仅通过**底部「返回首页」+「我的订单」**（以及可选：左上角关闭 = 返回首页），不再依赖系统返回键回到选座。

---

## 四、哪些页面可以/不可以返回（汇总）

| 页面 | 是否允许返回 | 说明 |
|------|--------------|------|
| play | 允许 | 返回上一级（如首页/影片详情） |
| seat-select | 允许 | 返回到 play 重新选场次，或放弃订单 |
| confirm-pay | 允许 | 返回到 seat-select 改座、换支付方式 |
| **ticketinfo** | **不回到选座/支付** | 用 reLaunch 进入后栈仅此页；出口仅「返回首页」「我的订单」 |

---

## 五、实施清单（你确认后再改代码）

1. **confirm-pay.js**  
   - `_redirectToTicketinfo`：跳 ticketinfo 改为 `wx.reLaunch`，订单号缺失时跳订单页也改为 `wx.reLaunch`。

2. **seat-select.js**  
   - `_navigateToTicketInfoPage`：两处跳转改为 `wx.reLaunch`（ticketinfo / order）。  
   - `_startM65PayStatusPoll` 内超时跳 ticketinfo：`redirectTo` → `reLaunch`。  
   - `_checkM65OrderStatusOnce` 内 SUCCESS 跳 ticketinfo：`redirectTo` → `reLaunch`。

3. **ticketinfo**  
   - 底部增加两个按钮：「返回首页」「我的订单」，并实现对应跳转。  
   - `onClose` 改为 `wx.reLaunch({ url: '/pages/index/index' })`（或你指定的首页路径）。  
   - 如需，在 ticketinfo 的 json 里可设置 `"navigationStyle": "default"` 保留导航栏，仅靠 reLaunch + 底部按钮即可达到「不能返回到选座」的效果。

## 六、可选增强（后续可做）

- **seat-select 进入时**：若 URL 或 globalData 能区分「从 pay 新建订单进入」与「从别处进入」，可在 onLoad 里对非新建流程做一次提示或拦截（当前方案仅靠 reLaunch 已能避免「从 ticketinfo 退回选座」）。
- **后端**：对已支付订单的 seat_list/座位更新做幂等或状态校验，避免重复提交（与本次前端防返回方案互补）。

## 七、已实施（2025-02 按方案改代码）

- **confirm-pay.js**：`_redirectToTicketinfo` 及订单号缺失分支改为 `wx.reLaunch`；会员卡支付成功无 outTradeNo 时改为 `wx.reLaunch` 订单页。
- **seat-select.js**：所有「支付成功 → ticketinfo」及「无订单号 → order」改为 `wx.reLaunch`；**onLoad 增加校验**：无 orderId 或 globalData.playOrder 不存在或 order.id !== orderId 时，视为非从 play 新建订单进入，`wx.reLaunch` 到首页。
- **ticketinfo**：底部增加「返回首页」「我的订单」按钮；`onClose` 改为 `wx.reLaunch` 首页；新增 `onGoHome`、`onGoOrder`。
